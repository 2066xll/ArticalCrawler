# 网络小说下一章获取功能实现计划

## 1. 功能需求
- 添加命令行参数，支持指定是否获取下一章以及获取的章节数量
- 在解析文章内容时，提取下一章的链接
- 支持不同的URL模式：
  - 原数字后加_2，如21341278.html -> 21341278_2.html -> 21341279.html
  - 直接增加数字（可能不连续），如21341292_2.html -> 21341295.html

## 2. 实现方案

### 2.1 命令行参数修改
- 添加`--next-chapters`或`-n`参数，指定要获取的下一章数量
- 默认值为0，表示只获取当前章节

### 2.2 下一章链接提取
- 在`parse_article`函数中添加提取下一章链接的逻辑
- 查找网页中常见的下一章链接元素，如：
  - `.next-chapter`、`.next`、`.chapter-next`等类
  - 包含"下一章"、"下节"、"Next"等文本的链接

### 2.3 循环爬取机制
- 在`main`函数中实现循环，根据指定的章节数量依次爬取下一章
- 每爬取一章后，使用提取的下一章链接继续爬取
- 当没有下一章链接或达到指定数量时停止

### 2.4 URL处理
- 不需要手动解析URL模式，直接使用网页中提取的下一章链接
- 这样可以适应不同网站的URL规则，避免手动处理各种复杂情况

## 3. 代码修改步骤
1. 修改`parse_args`函数，添加下一章参数
2. 在`parse_article`函数中添加下一章链接提取逻辑
3. 修改`main`函数，实现循环爬取功能
4. 测试不同URL模式的章节爬取

## 4. 预期效果
- 支持通过命令行指定获取下一章的数量
- 自动提取下一章链接，适应不同网站的URL规则
- 能够连续爬取指定数量的章节
- 保持良好的错误处理和日志记录
